# 影像 - AI 重绘 需求评审

- 评审日期：2026-10-27（v2，已回填确认决策）
- 评审范围：需求完整性与技术可行性评审，不含编码
- 需求原文要点：① 必须上传图片；② 提示词不可为空；③ 提示词模板（名称 / 正文 / 示例图，正文支持导入 md）；④ 支持 AI 优化提示词（system prompt 由评审方产出）；⑤ 弹窗选择模板，列表可预览示例图、示例图可点击放大；⑥ 重绘过程有进度动画

## 1. 评审结论

### 1.1 技术链路可行，且大部分能力已在本项目跑通

| 需求点 | 可行性 | 依据 |
| --- | --- | --- |
| 上传图片后重绘 | ✅ 高 | `image-edit.client.ts` 已用 `POST /v1/images/edits`（multipart 图生图）稳定出图，实测 35-60s，照片AI优化在用 |
| 单图上传与校验 | ✅ 高 | 照片点评 / 照片AI优化已有拖拽上传、data URL 预览、jpg/png/webp + 8MB 校验 |
| 进度动画 | ✅ 高 | `PhotoOptimizeView.vue` 已有「时间预估分段推进」的实现，可直接迁移并改名 |
| 模板存储与检索 | ✅ 中 | 需新增表 + 示例图落盘；名称检索可在前端本地过滤 |
| 弹窗选模板 + 示例图放大 | ✅ 高 | Element Plus `el-dialog` + `el-image`（`preview-src-list` 自带点击放大） |
| AI 优化提示词 | ✅ 中 | `llm-client.service.ts` 单轮 `chat/completions` 已可用，需新增独立 system prompt |
| 历史记录 | ⚠️ 中 | 需新增表 + 图片落盘 + 容量策略；单条记录约 3-10MB |

结论：**技术上没有不可逾越的障碍，功能可以在现有架构内闭环。**

### 1.2 需求成熟度已从「功能清单」提升到可开发

上一轮识别出 29 个缺口，本次确认了其中 24 个。剩余 5 项均为实现细节，不阻塞开工（见第 10 节）。

需要重点提示的两处**新增复杂度**（原需求未提及，确认后才出现）：

1. **历史记录入库**：每条记录要持久化原图 + 结果图 + 最终提示词。原图最大 8MB、结果图实测约 2.2MB，图片**必须落盘**而非入库，且必须有容量与清理策略，否则磁盘会持续增长。
2. **提示词「追加」语义**：手输内容后再选模板是**追加**而非替换，需要考虑分隔符、重复追加、超长截断，以及"用户其实想替换"的误操作。

### 1.3 已确认决策

| 决策项 | 结论 | 带来的新约束 |
| --- | --- | --- |
| 模板归属 | 用户端可自建，全局共享（无用户体系、无隔离） | 写接口位于公开侧、无鉴权；需防误删、需数量上限 |
| 工具形态 | 新建独立工具，不改造 photo-enhance | seed 增第 11 项、ToolIcon 登记、新增路由与页面 |
| 模板字段 | 暂不做分类标签、排序、启用状态、时间字段；**仅需按名称检索** | 表结构极简；删除为物理删除，需二次确认 |
| 示例图 | **最多 3 张，非必填** | 需子表存多图；列表需懒加载 |
| 正文长度 | **上限 10000 字** | 需验证上游 prompt 上限（见风险表） |
| 是否必须先选模板 | **不必**。可纯手输；手输后再选模板为**追加** | 需定义追加规则（见 4.3） |
| 无模板时 | 可正常使用，手输即可 | 无需预置模板，空状态仅需引导文案 |
| 正文编辑 | 可修改，不回存模板，仅本次生成生效 | 需明确提示改动不持久 |
| 提示词优化 | 纯文本改写，不发送原图；**全文优化，不截断输入** | 长文本带来上下文与耗时风险，需错误兜底（见 4.4） |
| 进度 | 模拟进度（时间预估） | 阶段名需重写为易读文案 |
| 历史记录 | **保留并入库**：原图、生成图、提示词正文；支持删除 | 需新增表、落盘目录、容量策略 |
| 预置模板 | 暂不预置 | 首次进入为空状态 |

```text
category: photography
icon: image（复用）或新增 brush
```

首页卡片副标题需区分定位：本工具写「模板驱动 · 创意重绘」，photo-enhance 写「场景驱动 · 修图优化」。首页网格为 `auto-fill`，加第 11 个工具不会破版。

### 4.6 进度与阶段命名

模拟进度已确认。上一版「准备提示词 → 提交重绘 → 接收结果」偏工程视角，改为面向用户的状态文案：

| 起始时间 | 阶段名 | 副文案 |
| --- | --- | --- |
| 0s | 正在读懂你的创意 | 梳理画面主体与风格 |
| 10s | 正在铺陈画面 | 构图、光线就位中 |
| 45s | 正在打磨光影与细节 | 质感与色彩细化中 |
| 100s | 即将完成 | 复杂画面会多花一点时间 |

要点：

- 时间锚点依据实测 35-60s 出图、最坏 150s 设定；阶段**只能前进，不回退**。
- 必须显示已用秒数（`已等待 42s`），并在 60s 后追加一行安抚文案（如"图像生成需要一点耐心，请勿关闭页面"），这是缓解焦虑的关键，进度条本身作用有限。
- 不展示百分比数字，避免用户拿"90%"和真实剩余时间做对账。
- 提交期间禁用图片替换、模板切换与重复提交。
- `prefers-reduced-motion` 下降级为静态文案 + 秒数，不播动画。
- 页面切走/刷新时必须清理定时器（现有 `PhotoOptimizeView` 有 `onUnmounted` 清 timer 的先例，照做）。

## 5. MVP 范围

### P0

1. 单图上传（jpg/png/webp，≤8MB）+ 预览 + 替换 + 移除。
2. 提示词输入框（≤10000 字，实时字数），支持纯手输提交。
3. 模板弹窗：卡片列表、最多 3 张示例图缩略、点击放大、按名称检索、空状态引导。
4. 选中模板 → 追加到现有正文（含重复检测、超长拒绝、撤销）。
5. 提交重绘：`images/edits` 单次调用，返回 1 张结果图。
6. 四段模拟进度 + 已用秒数 + 60s 后安抚文案 + 禁止重复提交。
7. 结果展示：原图/结果图对比、下载、重新生成。
8. 模板 CRUD（新建/改名/换图/删除），全局共享，带二次确认。
9. 历史记录：成功即入库，列表分页、详情对比、单项删除、清空。
10. 全链路错误分类（配置缺失 / 鉴权 / 限流 / 超时 / 空图 / 解码失败）。

### P1

- AI 优化提示词（附录 A.1）。
- 正文导入 Markdown（粘贴 + `.md` 文件）。
- 历史记录「回填提示词」与「再次生成」。
- 追加后「撤销」。

### P2（明确不做）

- 批量出图、多图参考、局部重绘（mask）、强度滑块、种子、negative prompt。
- 模板分类标签、启用状态、排序、审批流。
- 真实 SSE / 轮询进度。
- 缩略图服务（除非列表明显卡顿）。
- 跨设备同步、多用户隔离。

## 6. 数据模型

```sql
-- 模板主表（字段极简：不做分类/排序/启用状态/时间字段）
CREATE TABLE IF NOT EXISTS redraw_templates (
  id         INTEGER PRIMARY KEY AUTOINCREMENT,
  name       TEXT NOT NULL,
  body       TEXT NOT NULL
);
CREATE INDEX IF NOT EXISTS idx_redraw_templates_name ON redraw_templates(name);

-- 模板示例图（最多 3 张，非必填）
CREATE TABLE IF NOT EXISTS redraw_template_previews (
  id          INTEGER PRIMARY KEY AUTOINCREMENT,
  template_id INTEGER NOT NULL REFERENCES redraw_templates(id) ON DELETE CASCADE,
  path        TEXT NOT NULL,      -- 相对 data 目录，如 redraw/previews/12-0.jpg
  seq         INTEGER NOT NULL DEFAULT 0
);
CREATE INDEX IF NOT EXISTS idx_redraw_previews_tpl ON redraw_template_previews(template_id);

-- 历史记录（原图 / 结果图 / 实际提交的提示词）
CREATE TABLE IF NOT EXISTS redraw_history (
  id           INTEGER PRIMARY KEY AUTOINCREMENT,
  source_path  TEXT NOT NULL,     -- 相对 data 目录
  result_path  TEXT NOT NULL,
  prompt       TEXT NOT NULL,     -- 最终提交文本（含追加内容）
  template_id  INTEGER,           -- 仅记录来源，模板删除后置 NULL
  created_at   TEXT NOT NULL
);
CREATE INDEX IF NOT EXISTS idx_redraw_history_created ON redraw_history(created_at DESC);
```

文件目录：

```text
server-node/data/
  redraw/
    previews/     模板示例图
    history/      历史原图与结果图
```

要点：

- **只写 `data/`**：`docker-compose.yml` 中只有 `./server-node/data` 是持久化卷，写 `assets/` 会随镜像重建丢失。
- 图片通过专用只读接口流式返回（`Content-Type` + 长缓存），**不要走 `/static`**（它映射的是 `assets/`）。
- 建表放在 `initTables()` 保持幂等，只新增表，不动 `PRAGMA user_version`。
- `redraw_history.template_id` 不加外键，避免模板删除时级联清掉历史。


## 附录 A：AI 优化提示词的 system prompt

### A.1 纯文本版（采用）

```text
你是「AI 图像重绘」流程中的提示词优化助手。用户提供一段用于图生图（image-to-image）重绘的提示词，你需要在保留其核心创作意图的前提下改写它，使其更适合作为图像生成模型的输入。

优化原则：
1. 保留原意：不改变用户指定的主体、场景、风格方向和情绪基调；用户没提的主体不得擅自新增。
2. 具体化而非堆砌：把模糊表述替换为可视化的描述（构图、视角、镜头、光线方向与质感、色彩关系、材质、景深、画面层次），避免空洞的形容词堆叠。
3. 结构清晰：短输入（约 500 字以内）按「主体 → 环境与背景 → 构图与视角 → 光线 → 色彩与影调 → 材质与细节 → 风格与媒介 → 画面质量」的顺序组织；长输入**保留原文的段落划分与逻辑顺序，按段逐段优化**，不整体重排、不合并段落。统一用自然语言段落或短句表达，不使用标题、编号、markdown 语法。
4. 保护原图信息：这是图生图任务，输出中应包含对原图需保留内容的约束（如人物身份、关键物体、文字标识），避免模型过度改动。
5. 规避风险：不要生成涉及真实可识别个人、商标、受版权保护的具体作品名称的描述；不要添加暴力、色情、违法违规内容。
6. 长度控制：输出长度随输入自适应。原文较短时不强行扩写；原文较长时按段落逐段优化，**不压缩、不删减原文已有的有效信息**，输出长度可与原文相当。完整保留原文的结构与信息点是硬要求。
7. 语言一致：输出语言与输入语言保持一致。
8. 唯一输出：只输出优化后的提示词正文，不要解释优化思路，不要加引号，不要加代码围栏，不要输出"优化后："之类的前缀。

如果输入内容为空、无意义或明显不是图像描述，原样返回一个最简的通用重绘提示词，不要报错说明。
```

### A.2 多模态版（备选，本期不实现）

```text
你会同时收到用户上传的原图与待优化的提示词。请先读图，再改写提示词，使描述与原图的实际内容、构图和光线相符：
- 若提示词与原图明显矛盾（如原图是室内、提示词写海边），以用户提示词表达的创作意图为准，但描述要说明"在保留原图主体位置关系的前提下"如何过渡。
- 明确指出原图中必须保留的元素（主体位置、人物身份特征、文字、关键物体），作为重绘约束写入提示词。
- 若原图包含清晰可辨的人脸、品牌标识或文字，明确要求"保持原有面部特征/不新增或篡改文字"。
```

### A.3 调用建议

- 走现有 `chatCompletion()`（非流式），`reasoning_effort` 沿用配置。
- **输入为完整正文（≤10000 字），不做截断**，因此按长文本任务设定超时：后端 180s，前端同步。
- 上下文风险：10000 汉字约 1.3-1.5 万 token，须确认所选模型上下文窗口；上游报上下文超限时映射为 `PROMPT_OPTIMIZE_TOO_LONG`。
- 失败保留原文；允许重复点击，**不做自动重试**（避免重复计费）。
- 长文本 token 消耗显著高于短文本，loading 期间必须禁用按钮，避免误触反复计费。

- 长文本优化：10000 字全文提交、**不截断**；优化结果回填后原文信息点无缺失（分段抽查）；优化期间按钮禁用；超时 180s 有明确提示；上下文超限返回可读错误而非 500。
